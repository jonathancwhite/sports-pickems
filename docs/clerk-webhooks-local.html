Receiving Clerk webhooks on localhost

Clerk delivers webhooks from its own servers over the public internet, so it can't reach http://localhost:3001. Clerk has no CLI forwarder — there is no clerk listen equivalent to stripe listen. This guide uses a Cloudflare quick tunnel: free, no account, no request cap, one command.

What you're building

A temporary public HTTPS hostname that forwards to your local API, plus a Clerk development webhook endpoint pointed at it. 

Clerk  ──►  https://<random>.trycloudflare.com/api/webhooks/clerk
                          │
                          ▼
              http://localhost:3001/api/webhooks/clerk
                  (apps/api/src/routes/webhooks/clerk.ts)

Setup

  1. Install cloudflared

    Windows — already done on this machine

    Downloaded to %LOCALAPPDATA%\cloudflared\cloudflared.exe and added to your user PATH. The winget package needs admin rights; the portable exe below does not. Open a new terminal so the PATH change takes effect. 

    $dir = "$env:LOCALAPPDATA\cloudflared"
New-Item -ItemType Directory -Force $dir | Out-Null
Invoke-WebRequest -UseBasicParsing `
  -Uri "https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-windows-amd64.exe" `
  -OutFile "$dir\cloudflared.exe"

    macOS / Linux

    brew install cloudflared          # macOS
# Linux: see https://github.com/cloudflare/cloudflared/releases

    Verify with cloudflared --version.

  2. Start the app

    The tunnel forwards to port 3001, so the API has to be listening there.

    pnpm dev

    Confirm http://localhost:3001/api/health returns 200 before continuing.

  3. Open the tunnel

    In a second terminal, leave this running for the whole session:

    cloudflared tunnel --url http://localhost:3001

    It prints a banner containing your hostname:

    +---------------------------------------------------------+
|  Your quick Tunnel has been created! Visit it at:       |
|  https://pointed-sao-absolute-full.trycloudflare.com     |
+---------------------------------------------------------+
    The hostname changes every restart. Quick tunnels are ephemeral — each cloudflared tunnel --url run mints a new random name, so step 4 has to be repeated each session. If that churn gets annoying, create a named tunnel on a domain you own for a stable URL.

  4. Create the Clerk endpoint

    In the Clerk Dashboard, switch to your development instance → Webhooks → Add Endpoint. Set the URL to your tunnel hostname plus the route path: 

    https://<random>.trycloudflare.com/api/webhooks/clerk

    Subscribe to exactly the events the handler processes — anything else is dead traffic:

    • user.created
    • user.updated
    • user.deleted
    • subscription.created
    • subscription.updated
    • subscription.active
    • subscription.pastDue
    • subscriptionItem.canceled
    • subscriptionItem.ended

  5. Copy the signing secret

    On the endpoint's page, reveal the Signing Secret (whsec_…) and put it in your local .env: 

    CLERK_WEBHOOK_SECRET=whsec_xxxxxxxxxxxxxxxxxxxxxxxx

    Restart pnpm dev — the secret is read at request time from process.env, but the dev server needs to reload .env.

    Each endpoint has its own secret. Recreating the endpoint after a tunnel restart issues a new whsec_. Either update .env to match, or edit the existing endpoint's URL in place instead of deleting and re-adding it — the latter keeps the secret stable.

  6. Send a test event

    Clerk endpoint page → Testing tab → pick user.created → Send Example. You want a 200 with {"received":true}.

    End-to-end check: sign up in the local web app at http://localhost:5173 and confirm a User row appears — that exercises upsertUserFromClerk through the real delivery path, which a dashboard test event doesn't fully prove.

Troubleshooting

SymptomCause & fix
502 Bad Gateway Tunnel is up but nothing is listening on 3001. Start pnpm dev.
400 Webhook verification failed CLERK_WEBHOOK_SECRET doesn't match this endpoint's signing secret, or the API wasn't restarted after editing .env. Also check the raw-body note below.
404 Path is missing. The full URL must end in /api/webhooks/clerk.
Clerk shows delivery failures after a break The quick tunnel died. Restart it and update the endpoint URL to the new hostname.
Events fire but nothing happens Event type isn't handled. Only the nine types listed in step 4 do anything; everything else falls through the default branch silently.

Why the route is mounted first

In apps/api/src/index.ts, the webhook router is registered with express.raw() before express.json() and before clerkMiddleware(): 

app.use(
  "/api/webhooks",
  express.raw({ type: "application/json" }),
  clerkWebhookRouter,
);

app.use(express.json());
app.use(clerkMiddleware());

Svix signature verification hashes the unparsed request body. If the JSON parser runs first, the raw bytes are gone and every webhook fails verification with a 400. The route is also intentionally unauthenticated — the signature is its only gate.

Skipping the tunnel entirely

Because verifyWebhook only checks the Svix signature, you can sign a fixture payload with your local CLERK_WEBHOOK_SECRET and POST it straight at localhost:3001. That's a much faster loop for iterating on the subscription.* branches than triggering real billing events over and over. It does not validate that your fixture matches Clerk's real payload shape, so do one tunneled run against live events before shipping.
